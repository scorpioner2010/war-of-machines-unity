# UI HUD

Read this file before changing gameplay HUD, crosshair, reload/ammo display, map/player list HUD, pause HUD, or menu UI wiring.

Current owner scripts:
- `Assets/Game/Scripts/Gameplay/Robots/VehicleHUD.cs`
  - Robot-prefab world HP/vehicle-name HUD root and root-aware binding.
  - Owns rotating the world HP bar toward the gameplay camera and scaling it by camera distance.
  - Uses the serialized root `CanvasGroup` from `Assets/Game/Content/UI/Prefabs/World/NameCanvas.prefab` to fade the entire name/HP canvas by distance to `CameraSync.gameplayCamera`. `worldHpBarCanvasFadeStartDistance` keeps alpha at `1`, `worldHpBarCanvasFullyTransparentDistance` produces alpha `0`, and the interval between them is linear.
  - Subscribes to `VehicleHealth.OnHealthChanged` and `OnDamaged`, so the HP fill is initialized on spawn and updates on later health changes.
  - Consumes `VehicleRuntimeStats` and displays the robot name, falling back to its code and then prefab instance name until stats arrive.
  - Uses the same map/spotting visibility result as the vehicle model: the name and HP disappear when the robot disappears from the map.
  - While the robot remains present in the map visibility snapshot, overlay materials keep its name and HP visible through walls.
  - Floating damage text uses the same relation color as the world HP bar: `alliedHpColor` for allies and `enemyHpColor` for enemies; pooled text resets that color at the start of each animation.
  - Never displays the world vehicle name, HP bar, or floating damage text for the locally owned gameplay vehicle; the owner uses the screen-space HUD health display instead.
  - Never displays the world vehicle name or HP bar for a main-menu robot preview. `VehicleRoot.Init(true)` refreshes this gate after assigning the menu context.
  - `SetWorldCanvasHidden(true)` suppresses the selected robot's world-space name/HP canvas during death spectating, so its HP is presented only by the screen-space gameplay HUD; `CameraController` clears it when the target changes or is destroyed.
  - HP team color is resolved through `VehicleTeamRelationResolver`, which uses `SpectatorTeamContext` after the local vehicle despawns. A missing `LocalPlayerVehicle` no longer defaults every world HP bar to enemy red.
- `Assets/Game/Content/UI/Prefabs/World/NameCanvas.prefab` assigns overlay materials to its TMP text and HP images and wires the root `CanvasGroup` to `VehicleHUD.nameCanvasGroup`. Production IA/NV robot prefabs inherit this shared nested-prefab binding; their instances are covered by `Assets/Editor/VehicleHudCanvasFadeEditModeTests.cs` so no per-robot duplicate CanvasGroup override is required. Those materials use the Overlay render queue with `ZTest Always`, and the Canvas overrides sorting at order `32767`, so map geometry and walls do not occlude the presentation.
- `Assets/Game/Scripts/Gameplay/Robots/VehicleClientVisibility.cs`
  - Client-only presenter for the spawned vehicle's 3D visibility.
  - Reads the local team's authoritative snapshot from `GameplayMapVisibilityState` by FishNet object ID.
  - Caches the assigned local team before owner despawn, so living allies remain visible while death spectator mode has no `VehicleRoot.LocalPlayerVehicle`.
  - Keeps the owner and assigned allies visible. A directly spotted enemy (`Enemy`) is rendered in 3D; `EnemyLastKnown` keeps only its map marker and does not reveal the live model. Destroyed entries use their own map/death presentation.
  - The server-side team snapshot preserves direct visibility for every confirmed allied spotting source until that source is rechecked; the client therefore does not hide a live enemy merely because the current raycast budget did not reach its pair. The enemy model and `NameCanvas` hide only after all direct sources are lost, while the map may retain an `EnemyLastKnown` marker until its memory expires.
  - `CameraController` temporarily overrides this presentation rule for the active death-spectator target, keeping the camera's selected live robot rendered even when it is not in the local enemy visibility snapshot; the override has priority over the first client-start refresh, and target changes and camera teardown restore the previous snapshot result.
  - Uses the prefab-configured renderer list and `Renderer.forceRenderingOff`; it does not disable the network object, gameplay components, colliders, or simulation.
  - Clears hover outline while hidden. `VehicleAutoAimController` and `VehicleHoverOutline` also reject targets whose presenter is hidden.
  - Refreshes on visibility snapshots, local-player changes, and `VehicleNetworkInitializer.ClientTeamChanged`, covering teams assigned by the server after FishNet spawn.
- `Assets/Game/Scripts/Gameplay/Robots/VehicleHudInitializer.cs`
  - Initializes HUD for a vehicle owner and owns the only `SpeedHud` writer.
  - During death spectating, subscribes to `CameraController.SpectatorTargetChanged` and samples the selected target's inspector-wired `VehicleMovementController` transform with the existing interval, multiplier, smoothing, and stop-snap settings; changing targets resets the display to zero before sampling the new robot.
- `Assets/Game/Scripts/Gameplay/HealthBar.cs`
  - Inspector-wired holder for the local vehicle HP slider/fill image, HP value, and vehicle-name label in `Client.unity/Canvas/GameplayHUD/GameplayHudContent/GameplayHudPanels/VehicleStatusPanel`.
  - `SetNormalizedValue` updates either the legacy `Slider` or the new `Image` fill, so the `VehicleStatusPanel/barHp` image can replace the removed slider without changing the health presenter.
- `Assets/Game/Scripts/Gameplay/Robots/HealthBarUI.cs`
  - Drives the local owner's screen-space HP panel.
  - Shows the runtime vehicle name above the HP bar, falling back to the vehicle code and then the prefab instance name until runtime stats are available.
  - Updates only the HP amount on `VehicleStatusPanel/barHp`; it does not override the `Image.color` authored in the HUD Inspector.
  - During death spectating, follows `CameraController.SpectatorTarget` through its target-change event and binds/unbinds `VehicleHealth` events without scene searches. The same panel therefore shows the selected living allied robot's name and current/max HP while `GameplayHUD` remains open; the local dead robot remains the only dead-target exception.
- `Assets/Game/Scripts/UI/HUD/DamageScreen.cs`
  - Fullscreen local hit indicator in the scene-owned `Client.unity/Canvas/GameplayHUD` hierarchy.
  - Subscribes to `VehicleRoot.LocalPlayerVehicleChanged`, then to the local vehicle `VehicleHealth.OnDamaged`.
  - Flashes a red fullscreen `Image` through a serialized `CanvasGroup`.
  - On damage, enables the image immediately at canvas group alpha 1, fades alpha to 0 over 1 second, then disables the image object. It is visual only and does not affect gameplay.
- `Assets/Game/Scripts/UI/HUD/GunCrosshair.cs`
  - Gun crosshair UI, reload/ammo text, dispersion display target for weapon systems.
  - Applies the server-synchronized dispersion diameter directly to the active reticle `RectTransform`; a finite zoom-profile `aimingCircleDiameter` is the fully aimed base size, so values such as `1.01`, `20`, and `400` are preserved at full aim without the legacy global maximum, while current dispersion above fully aimed adds bloom. Values below `1` are clamped by the presenter to `1x1`. The legacy no-profile path uses the global minimum/maximum UI limits and current zoom scalar.
  - The new `GameplayHudContent` wiring uses `AmmoCountText` for remaining ammunition, `ReloadStatusText` for reload status, `AimStatus` for the aim label, `GameplayHudContent` as the regular HUD root, and `SniperScopeOverlay` as the scope overlay.
  - Owns the inspector-wired faction reticle bindings: `CrosshairType1` for `RobotFaction.IronAlliance` and `CrosshairType2` for `RobotFaction.NovaSyndicate`; the active local reticle, optional server reticle, reload fill, reload text, ammo text, aim-status text, and penetration-status text are switched together so every HUD calculation follows the selected robot.
  - During death spectating, follows `CameraController.SpectatorTarget` and presents that target's observer-visible ammo, reload state/progress, faction, and server-synchronized dispersion in the same HUD; the local owner's weapon presenters stop overwriting these values.
  - When the selected spectator target is the local destroyed robot, both faction `CrosshairType` roots are hidden. Selecting a living allied target restores only its faction root; normal owner crosshair behavior remains unchanged.
  - `CameraController` treats every forward zoom profile with `showReticle = true` as sniper presentation: the regular HUD is replaced by the black `SniperScopeOverlay` and central sniper reticle, while the profile's camera/FOV values remain authoritative. The wheel can move between multiple flagged profiles without hiding the overlay. This flag controls the scope overlay, not the ordinary projectile-dispersion ring.
  - `WeaponReloadController` receives a binding-change result and forces the current ammo/reload values into the newly selected target, preventing cached IA values from leaving the NV UI stale. Aim-status caches are also invalidated when the target text changes.
  - Initializes the active penetration-status label to `PENETRATION STATUS` and preserves the last shot result when the faction reticle changes. Manual control presents `Penetrated` or `No penetration`; autonomous control presents `〰〰〰` for those two results, while `Miss` remains explicit.
  - Owns the serialized `CrosshairType2` `lightElement` image list and changes only those images' alpha from the local weapon charge progress. It preserves each element's authored RGB color. The active faction reload circle uses the same progress, resets immediately when progress decreases, and smoothly fills toward higher progress.
  - The bindings are serialized on the scene `GunCrosshair` presenter and target `Client.unity/Canvas/GameplayHUD/GameplayHudContent/CrosshairType1` and `CrosshairType2`; the scene assigns all 12 Nova `lightElement` `Image` components explicitly.
- `Assets/Game/Scenes/Client.unity/SniperScopeOverlay/SniperScopeMask`
  - Fullscreen procedural sniper-scope vignette. Its standard UI `Image` is tinted black at alpha `0.72`, uses `Assets/Game/Content/UI/Materials/ProceduralSniperScopeMask.mat`, and intentionally has no sprite.
  - The material uses `Assets/Game/Content/Rendering/Shaders/ProceduralSniperScopeMask.shader`, which calculates a signed-distance circular aperture per pixel rather than sampling a scope PNG. `Aperture Radius (Screen Height)` is the radius normalized to the display height; the default `0.373` matches the former `Hud_Aim_Bracket.png` opening. `Aperture Center (UV)` moves the opening, and `Extra Edge Softness (Pixels)` adds optional softness beyond the shader's one-pixel antialiasing.
  - The RectTransform must stretch to its `SniperScopeOverlay` parent with zero offsets. `SniperScopeOverlay` is activated from `CameraController` and fades its serialized `CanvasGroup`; the shader consumes UI vertex alpha, so the existing fade remains authoritative.
- `Assets/Game/Scripts/UI/HUD/CameraCrosshair.cs`
  - Owns the simple center crosshair. It records show/hide requests received before the inactive `GameplayHUD` first runs `Awake()`, then applies the last requested state after registration. This keeps the first local-vehicle spawn from being lost to `UIScreenBase.Awake()` hiding the visual child.
- `Assets/Game/Scripts/Gameplay/Robots/WeaponReticlePresenter.cs`
  - Positions/presents the reticle from the weapon aim point through the existing exponential canvas interpolation.
  - Uses the current aim point supplied by `WeaponAimController`; auto-aim and manual gun-ray paths remain owned by the upstream vehicle input/aim systems.
- `Assets/Game/Scripts/Gameplay/Robots/WeaponReloadController.cs`
  - Updates reload/ammo HUD state for the owner during normal play and exposes observer-safe synchronized ammo, reload, duration, and faction values for the selected death-spectator target.
  - Passes the selected vehicle faction to `GunCrosshair` and presents the local predicted/server-reconciled reload progress to the active reload circle and Nova Syndicate `lightElement` indicators; spectator presentation uses the selected target's synchronized state and does not alter fire validation.
- `Assets/Game/Scripts/Gameplay/Robots/NetworkWeaponShooter.cs`
  - Applies local and authoritative crosshair dispersion to the owner HUD through the legacy `GunDispersionGlobalSettings.GetUiDiameter` formula, including global UI min/max limits and distance/zoom pixels-per-degree settings.
  - Uses the synchronized server-authoritative dispersion value for both the visible local ring and the `AimStatus` progress; the client-only dispersion model is used only until the first server value arrives.
  - Exposes the observer-visible synchronized dispersion range/current value for the selected spectator target; spectator ring sizing uses the local spectator camera zoom with that target's server dispersion.
  - Reads a normalized zoom scalar from `CameraController.GetAimUiZoom01`; default zoom maps to the legacy distance endpoint and the first flagged forward profile maps to the legacy max-zoom endpoint, with the last forward profile as fallback when none is flagged.
- `Assets/Game/Scripts/UI/HUD/GameplayGUI.cs`
  - Gameplay GUI root.
  - Keeps the legacy shot-result entry point compatible, but forwards results to the active `GunCrosshair`; penetration results use explicit manual text or the autonomous-only `〰〰〰` glyph and are not cleared by a timeout.
  - Owns the inspector-wired `zoomLevelTexts` references for both HUD crosshair variants and displays the signed camera zoom step: `0` is default, negative values are backward wheel steps, positive values are forward wheel steps, and the sniper profile uses the next positive step.
- `Assets/Game/Scripts/UI/HUD/GameplayHudRuntimeBinder.cs`
  - Runtime HUD binding support. `Client.unity/Canvas/GameplayHUD` has the serialized root Canvas reference, so its crosshair uses the same Canvas as the other client menus.
  - The active gameplay hierarchy is `GameplayHUD/GameplayHudContent`; its panels are grouped under `GameplayHudPanels`, with `VehicleStatusPanel` and `MatchTimerPanel` as named status groups.
- `Assets/Game/Scripts/Testing/VehicleTestSceneController.cs`
  - Legacy `VehicleTest` bootstrap can instantiate its configured HUD prefab, while Client test mode binds directly to the existing scene-owned `Client.unity/Canvas/GameplayHUD` object and never instantiates or destroys UI.
  - Registers and opens the HUD through `MenuManager` when present; otherwise opens the HUD `Menu` directly because VehicleTest has no scene `MenuManager`.
  - Hides the scene-owned `GameplayHUD` while the centered expanded test panel is open, then reopens it when the panel is collapsed or vehicle control resumes. The test panel is responsive: it scales with the screen and switches its vehicle catalog/statistics card from two columns to a vertical layout on narrow screens.
  - Rebinds `GunCrosshair` canvas references against the scene Canvas.
  - When the test controller spawns the test player or a bot, it directly binds the prefab's `VehicleHUD` to the test camera, vehicle root, and nickname so the standard in-world HP bar is visible and scales/rotates correctly.
- `Assets/Game/Scripts/UI/HUD/GameplayMapHud.cs`
  - Gameplay map HUD for `MiniMapRoot` and `FullMapRoot`.
  - Keeps `MiniMapImage` and the independent `MiniMapRobotCanvas` as separate presentation layers: image scale/X/Y/offset changes do not scale or move the robot marker coordinate canvas.
  - Keeps `FullMapImage` and the independent `FullMapRobotCanvas` as separate presentation layers as well, so full-map alignment is not affected by mini-map tuning.
  - Reads separate full-map and mini-map image scale/X/Y/offset, robot-canvas scale/X/Y/offset, marker X/Y scale, and marker offset from `ClientSettings.gameplayRuntime` every frame, so both map views can be tuned during Play Mode without changing the scene hierarchy.
  - Keeps `mapTrackedVehicleIconScale` as the relative size of tracked robot markers compared with the local-player marker; existing markers are resized immediately when the setting changes.
  - Continues refreshing tracked ally/enemy markers during death spectator mode after the local network vehicle is despawned; only the dead local-player icon is hidden.
  - Cloned tracked-vehicle markers receive the serialized `friendly_marker.png` or `enemy_marker.png` sprite while visibility, relation color, and destroyed-state behavior continue to come from `GameplayMapVisibilityState`.
- `Assets/Game/Scripts/UI/HUD/GameplayMapVisibilityState.cs`
  - Shared client visibility snapshot state used by both the map and vehicle visibility presenters.
  - Stores `Enemy` for direct team spotting and `EnemyLastKnown` for spotted-memory map markers.
  - Provides relation lookup by FishNet object ID without scene/component discovery.
  - Rejects duplicate or older network snapshot versions so an out-of-order packet cannot restore an already hidden enemy.
  - Stores a local deadline for finite enemy entries. Remaining server lifetime is reduced by FishNet snapshot age, and expired entries are removed even if the final empty snapshot is dropped.
- `Assets/Game/Scripts/UI/HUD/GameplayPlayerListHud.cs`
  - Player list HUD for ally/enemy rows under the scene-owned `GameplayHUD` containers.
  - Auto-tracks active non-menu `VehicleRoot` instances, binds each row to `VehicleHealth`, and refreshes names, vehicle type, synchronized kill count, HP, death state, and team relation.
  - Uses `VehicleTeamRelationResolver` for row relation and HP color, so TeamA and TeamB spectators retain the correct ally/enemy colors after local owner despawn.
  - A row that has received a dead state remains in its ally/enemy list after the server despawns that robot; it keeps the final name, vehicle type, kill count, and zero-HP/dead presentation for the rest of the active HUD session. The row releases its destroyed vehicle/health binding, while a missing row that was not dead is removed.
  - Clears instantiated row items when the HUD is disabled or the local player vehicle becomes null, so rows from a completed battle do not persist into the next battle.
- `Assets/Game/Scripts/UI/HUD/GameplayPlayerListItem.cs`
  - Presents each ally/enemy row from `Assets/Game/Content/UI/Prefabs/GameplayPlayerListItem.prefab`, including a compact `K:n` kill-count column.
- `Assets/Game/Scripts/Gameplay/Robots/VehicleNetworkInitializer.cs`
  - Synchronizes each spawned vehicle's current kill count from the authoritative server so every client player-list row can display it.
- `Assets/Game/Scripts/UI/HUD/GameplayTimerDisplay.cs`
  - Match timer display. It consumes the existing authoritative seconds value and formats it as `HH:MM:SS`; hours are not limited to a 24-hour clock.
- `Assets/Game/Scripts/UI/HUD/PauseMenu.cs`
  - Pause menu behavior.
  - `GameplayPausePopup` is a separate direct child of `Client.unity/Canvas`, not a child of `GameplayHUD/GameplayHudContent`. `GameplayPauseController` remains the serialized `MenuType.GameplayPause` registration point and still targets that popup's `Menu` component.
  - Suppresses normal gameplay pause handling whenever the `VehicleTest` scene is loaded, not only when it is the active scene, so additive test maps do not open centered pause UI or hide `GameplayHUD`.
- `Assets/Game/Scripts/MenuController/MenuManager.cs`
  - Global menu state; also affects gameplay input blocking.
  - Registers only inspector-wired scene menus during `Awake`; it does not instantiate menu prefabs at runtime.
  - `Client.unity/Canvas/GameplayHUD` is the inspector-wired `MenuType.GameplayHUD` route and owns the live gameplay crosshair, map, player list, damage screen, and local HP display.
  - `GameplayPauseController` registers the separate `GameplayPausePopup` route, so opening pause does not require nesting the popup under the gameplay HUD presentation root.
- `Assets/Game/Scripts/MenuController/Menu.cs`
  - Menu presentation controller used by HUD/pause/settings menus. It fades its inspector-wired `CanvasGroup` alpha without moving the UI layout; each component's `fadeDuration` controls both directions and defaults to `0.5` seconds.
  - Provides `CloseImmediate()` for VehicleTest to hide `GameplayHUD` instantly without a fade animation fighting the test overlay visibility.

Rules when editing HUD/UI:
- Keep gameplay input blocking behavior in sync with `VehicleInputController.IsGameplayInputBlockedByUi`.
- Do not let client-only UI state drive authoritative gameplay.
- Prefer inspector-wired references for UI components.
- Keep map markers and `NameCanvas` activation on the authoritative snapshot, but do not equate a memory marker with a visible 3D enemy: `Enemy` renders the model, while `EnemyLastKnown` is map-only. Rendering through walls applies only while direct spotting still contains the robot.
- Keep `NameCanvas` fade visual-only: alpha `0` must not disable the root `VehicleHUD`, because it still owns HP/name binding and may be the selected spectating target. The fade distance is measured against the shared gameplay orbit camera, not a per-robot camera.
- For local hit feedback, use `DamageScreen` and `VehicleHealth.OnDamaged`; do not poll health or search for the local vehicle from the scene.
- Keep Client menus and HUD in their owning scene. Client test mode must use its serialized `sceneGameplayHud` and `sceneGameplayCanvas` references; do not split one menu between scene objects and prefabs.
- Keep the existing `Client.unity/Canvas/GameplayHUD` assigned to the `GameplayHUD` entry of the scene `MenuManager`; do not add a second HUD instance or spawn UI at runtime.
- Keep `Client.unity/Canvas/GameplayPausePopup` outside `GameplayHUD`; its `GameplayPauseController` owns the pause menu registration and `GameplayHUD` remains the gameplay presentation layer.
- If weapon HUD changes, update `weapons-damage.md` too.
- If menu input blocking changes, update `robot-control.md` too.

Autonomous control UI:
- `Assets/Game/Scripts/UI/HUD/PauseMenu.cs` owns the inspector-wired green `Client.unity/Canvas/GameplayPausePopup/ButtonAutonomousControl` button. It mirrors the synchronized local vehicle state, changes its label between enable/disable, and closes the pause menu after a request.
- `Assets/Game/Scripts/UI/HUD/GameplayGUI.cs` owns the inspector-wired `GameplayHUD/Crosshair/AutonomousControlIndicator` TMP label. It is hidden unless the local `VehicleInputController.IsAutonomous` state is active and pulses alpha with unscaled time, so the indicator remains smooth while pause/time presentation changes.
- The static button and indicator are authored in `Assets/Game/Scenes/Client.unity`; neither is created or discovered at runtime.
