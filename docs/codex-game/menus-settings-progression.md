# Menus Settings And Progression UI

Read this file before changing main menu, settings screens, development tree, vehicle selection UI, profile display, or menu state transitions.

Current owner scripts:
- `Assets/Game/Scripts/MenuController/MenuManager.cs`
  - Global menu state and menu open/close events. It registers only serialized scene-menu references and does not instantiate menus at runtime.
- `Assets/Game/Scripts/MenuController/Menu.cs`
  - Shared menu presentation. Every routed menu fades its assigned `CanvasGroup` alpha from `0` to `1` when opening and from `1` to `0` when closing, never changing the menu `RectTransform` position and bringing its own root to the front.
  - Its serialized `fadeDuration` is the duration in seconds for both directions; it defaults to `0.5` and is clamped to zero or above in the Inspector.
- `Assets/Game/Scripts/MenuController/MenuType.cs`
  - Menu enum used by menu routing and input blocking.
- `Assets/Game/Scripts/UI/MainMenu/MainMenu.cs`
  - Main menu root, settings/development tree buttons, profile display values, and the persistent right-side statistics panel for the selected vehicle.
  - Calls `ProfileServer.UpdateProfile()` when main menu opens.
  - Opens `FreeXpConversionPopup` when the `freeXp` control is clicked.
  - Opens the scene-owned `ProfileStatisticsPopup` when `ButtonProfile` is clicked. The scene keeps a persistent Button `onClick` call to `ShowProfileStatisticsPopup`; the serialized `profileButton` runtime listener remains as a fallback and the method brings the popup to the top of the Canvas.
  - `HideProfileStatisticsPopup` delegates to `ProfileStatisticsPopup.Close` when the view is wired, so closing clears dynamic rows and deactivates the popup root.
- `Assets/Game/Scripts/UI/MainMenu/ProfileStatisticsPopup.cs`
  - Requests authenticated live statistics through `ProfileServer`, fills the general statistics, played-vehicle rows, selected-vehicle panel, selected-vehicle record bar, and catalog icon, and exposes explicit loading, empty, offline, error, and close states.
  - `RecordPanel` is driven by the selected `VehicleStatisticsDto`: `WinsBar.fillAmount` is `wins / (wins + losses)` clamped to `0..1`, `WinsLabel` and `LossesLabel` display whole percentages whose sum is `100%`, and the serialized `Background` image stays at `1`. Loading, unavailable, error, and no-selection states reset the bar safely.
- `Assets/Game/Scripts/UI/MainMenu/ProfileVehicleRow.cs`
  - Owns the selected-row background color for the profile vehicle list. `ProfileStatisticsPopup` resets every row and then marks only the clicked/default row selected, so the first row returns to its normal color when another robot is chosen.
  - Uses the serialized `vehicleIcon` `Image` to assign `GameResourceManager.GetIcon(vehicle.code)` for each row. The icon is disabled when the vehicle code is empty or not present in `RobotRegistry`.
- `Assets/Game/Scenes/Client.unity` → `Canvas/ProfileStatisticsPopup`
  - Scene-owned profile/statistics popup placeholder placed beside `FreeXpConversionPopup` as a separate direct Canvas child.
  - The inactive root contains `ProfileStatisticsWindow`, a general-statistics strip with five cards, `RobotsPlayedPanel` with a vertical `ScrollRect`/`Viewport`/`Content`, a serialized inactive `ProfileVehicleRowTemplate`, `VehicleStatisticsPanel` with a replaceable vehicle-preview slot and four stat cards, `RecordPanel`, and `CloseButton`.
  - The layout uses the existing `InfoPanel.png` and `Button_Default.png` sprites plus standard Unity UI Images with distinct olive, blue, amber, red, and green tints; no new artwork is required.
  - The root is intentionally inactive by default. `MainMenu.profileButton` and `MainMenu.profileStatisticsPopup` are assigned, and `ButtonProfile` also has a persistent scene `onClick` call to `MainMenu.ShowProfileStatisticsPopup`; clicking the button activates the popup and brings it to the top of the Canvas.
  - `ProfileStatisticsPopup` is wired to the existing TMP/Image/Button fields plus the row template/content through serialized Inspector references. It instantiates one selectable row per returned played vehicle, selects the first row initially, and updates the right-hand vehicle panel, record percentages/bar, and icon when another row is clicked. Production profile values are never fabricated on the client; offline menu test mode intentionally supplies local demo statistics, dynamic rows are cleared for loading/empty/error states, and the Close button is raycastable and hides the root through the presenter.
  - `ProfileVehicleRowTemplate` uses `ProfileVehicleRow` as the only selection-color owner: its native Button transition is `None` and `ButtonComponent.childGraphics` is empty, preventing generic button state colors from restoring the first row's authored green background after another row is selected.
  - `ProfileVehicleRowTemplate/VehicleIcon` is a serialized, non-raycastable `Image`; generated rows fill it from each vehicle's registry code and hide it when no catalog icon is available.
- `Assets/Game/Scripts/UI/MainMenu/FreeXpConversionPopup.cs`
  - Show the current Free XP balance, populate a native `TMP_Dropdown` with the player's owned vehicles, and convert the selected whole-number slider amount into XP for the selected owned vehicle.
  - Keep Convert disabled until a vehicle and a positive amount are selected; Close hides the popup without sending a request.
  - `Client.unity/FreeXpConversionPopup` owns the serialized `vehicleDropdown` `TMP_Dropdown`. `FreeXpConversionPopup` adds the `Choose vehicle` entry plus owned vehicles, maps `onValueChanged` back to the selected vehicle, and relies on the native template/list lifecycle to close the list after selection.

  - A `TreeItem` click only selects a vehicle; it never starts purchase or research directly. `DevelopmentTree` keeps one `_selectedTreeItem`, disables its previous `IsSelect` child before enabling the newly clicked item's child, and clears the selection when changing faction or rebuilding the runtime tree.

- `Assets/Game/Scripts/UI/Tree/TreeItemBlink.cs`
  - Runs on the root of `TreeItem.prefab` and animates the serialized `Image (0)` through `Image (3)` references together.

- `Assets/Game/Scripts/UI/Settings/*.cs`
  - Settings tabs and settings model/view/controller. Their controls are authored and wired as serialized primitive UI objects in `Assets/Game/Scenes/Client.unity`; the views only bind values and events at runtime.
  - `GeneralTabView` owns the Server crosshair and Camera shake toggles, `ControlsTabView` owns gameplay and sniper mouse-sensitivity sliders, and `VideoTabView` owns FPS-limit and vertical-sync controls.
  - `VideoTabView` owns four serialized native `TMP_Dropdown` controls for screen mode, resolution, quality, and frame rate. It fills each with `ClearOptions`, `AddOptions`, `SetValueWithoutNotify`, and `onValueChanged`; VSync directly changes the frame-rate dropdown's `interactable` state.
  - `SettingsView` disables the Video-tab `ApplyButton` while the saved video baseline matches the current dropdown, toggle, and gamma-slider values. `VideoTabView` raises `PendingChangesChanged` after each video-control edit and refreshes that baseline after Apply; other settings tabs retain their existing Apply behavior.
  - Every project-owned dropdown in `Client.unity` uses an inactive `Template → Content → Toggle` hierarchy, but its `Content` and template-item `Toggle` children stay active. This is required for `TMP_Dropdown.SetupTemplate()` to discover and clone the item when it temporarily activates the template. Every option template item uses horizontal stretch anchors (`x: 0` to `1`), top vertical anchors, `anchoredPosition.y: -18`, and a `36`-pixel height. The negative half-height positions the sample pivot inside the top edge so `TMP_Dropdown` calculates the correct top and bottom offsets before positioning generated rows. A zero `anchoredPosition.y` clips the first row and leaves unused backing below it; centered horizontal anchors would make cloned rows zero-width and invisible. Selectors remain `322 x 40`; templates keep the current sprites, colors, text font/size/margins, and a maximum `180`-pixel list height. The content starts at `44` pixels, so `TMP_Dropdown` shrinks short lists to their rows and lets larger lists use the existing `ScrollRect`. Its built-in blocker prevents a second dropdown from opening while one list is active.
  - `Client.unity/Settings` uses Video as the visual reference for all tab controls. General toggles are centered at X `77.64`, are `322 x 32`, and retain the same checkbox/label setup as Vertical sync. Controls and Sounds sliders are centered at X `77.64`, are `322 x 40`, and have rows at Y `297`, `237`, and, for SFX, `177`; their labels are at X `-195` and use `160 x 60` bounds.
  - Every settings slider uses the same serialized frame, fill, and handle sprites as Video Gamma: `Unused/Backgrounds/Bar/loading_cell_ai_attempt_rejected.png`, `loading_cell_ai_attempt_rejected 1.png`, and `Unused/Backgrounds/icons/profile_icon_losses_skull.png`. These are presentation-only scene values; the existing tab views and serialized Slider/Toggle references remain the owners of interaction and settings values.

Important behavior:
- `Assets/Game/Scripts/UI/Lobby/EndGameUI.cs` displays the short tactical snapshot before `GameResultUI`: the existing TMP `status` field renders the outcome, authoritative map name, fixed current mode `TEAM BATTLE`, elapsed match duration, and team kill score in a structured rich-text layout. The snapshot arrives through `GameplaySpawner` from `ServerRoom.selectedLocation`, the server gameplay timer, and each `Player.kills`; missing map data falls back to `UNKNOWN MAP`. The existing EndGame delay and `OK` return-to-main-menu flow remain unchanged, and no new scene objects or image assets are required.
- `Assets/Game/Scripts/UI/Lobby/GameResultUI.cs` displays post-battle results only after the main menu is available. It renders the existing single TMP text element as a structured rich-text report: a bronze-gold `MISSION DEBRIEF` header, outcome-specific `VICTORY`/`DEFEAT`/`DRAW` color, separated `REWARDS` and `COMBAT PERFORMANCE` sections, and color-emphasized values. XP, Bolts, Free XP, and MMR are shown as confirmed values only when `PlayerBattleResult.RewardsAvailable` is true; a missing or incomplete API reward record uses the same structured layout with an amber `REWARDS / SYNCHRONIZING` state and pending values, while server-authoritative kills and damage remain visible. The server must deliver the EndGame menu to every still-connected non-bot player before this queue waits for MainMenu; a despawned dead vehicle does not remove that player from the result flow. Closing the popup confirms the result delivery and refreshes the player profile. The presentation uses TMP tags only and does not require new scene objects or image assets.

Rules when editing menus:
- Author every new static menu, popup, and settings control manually from Unity UI objects in `Assets/Game/Scenes/Client.unity` (or in its owning UI prefab), then assign its dependencies through serialized inspector references.
- Runtime UI views may bind data, visibility, and events only. Do not create static controls with `new GameObject` or `AddComponent`, and do not locate required UI controls through `Find` or `GetComponent` calls.
- Keep menu state changes consistent with gameplay input blocking.
- Do not let menu-only code affect server-authoritative gameplay.
- If profile fields or vehicle selection changes, update `api-resources.md` too.
- If gameplay HUD behavior changes, update `ui-hud.md`.
- Add a Ukrainian explanation with a practical example to `Assets/Editor/ClientSettingsEditor.cs` whenever `ClientSettings` gains a serialized field, including nested settings.
