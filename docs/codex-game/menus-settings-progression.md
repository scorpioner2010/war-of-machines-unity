# Menus Settings And Progression UI

Read this file before changing main menu, settings screens, development tree, vehicle selection UI, profile display, or menu state transitions.

Current owner scripts:
- `Assets/Game/Scripts/MenuController/MenuManager.cs`
  - Global menu state and menu open/close events. It registers only serialized scene-menu references and does not instantiate menus at runtime.
- `Assets/Game/Scripts/MenuController/Menu.cs`
  - Shared menu presentation. Every routed menu fades its assigned `CanvasGroup` alpha from `0` to `1` when opening and from `1` to `0` when closing, never changing the menu `RectTransform` position and bringing its own root to the front.
  - Its serialized `fadeDuration` is the duration in seconds for both directions; it defaults to `0.5` and is clamped to zero or above in the Inspector.
- `Assets/Game/Scripts/MenuController/MenuType.cs`
  - Menu enum used by menu routing and input blocking.
- `Assets/Game/Scripts/UI/MainMenu/MainMenu.cs`
  - Main menu root, settings/development tree buttons, profile display values, and the persistent right-side statistics panel for the selected vehicle.
  - Calls `ProfileServer.UpdateProfile()` when main menu opens.
  - Opens `FreeXpConversionPopup` when the `freeXp` control is clicked.
- `Assets/Game/Scripts/UI/MainMenu/FreeXpConversionPopup.cs`, `FreeXpVehicleOption.cs`
  - Show the current Free XP balance, build a hidden dropdown list from `PlayerProfile.ownedVehicles`, and convert the selected whole-number slider amount into XP for the selected owned vehicle.
  - Keep Convert disabled until a vehicle and a positive amount are selected; Close hides the popup without sending a request.
  - `Client.unity/FreeXpConversionPopup` uses the Settings visual system without changing these serialized interaction references: a `620 x 520` `matchmaking_panel_blank` panel; a `322 x 40` `profile_general_statistics` vehicle dropdown with the `tree_icon_research` arrow; and a matching `322 x 40` Gamma-style slider (`loading_cell_ai_attempt_rejected`, its fill variant, and `profile_icon_losses_skull` handle). The `322 x 180` option list uses `slot_empty_05`; option rows and the `160 x 60` Convert/Close controls use `popup_login_button_background`.
- `Assets/Game/Scripts/UI/MainMenu/VehicleItemView.cs`
  - Vehicle list item view.
- `Assets/Game/Scripts/UI/MainMenu/VehicleSlotView.cs`
  - Vehicle slot display and vehicle-selection click handling. It does not create a hover specifications popup.
- `Assets/Game/Scripts/UI/MainMenu/RobotView.cs`
  - Main menu robot preview display and vehicle slot generation.
  - Sends the selected vehicle's resolved API stats to `MainMenu.UpdateVehicleInfo` after rebuilding the slots.
  - Initializes preview vehicles through `VehicleRoot.Init(true)`. Menu context keeps the robot model visible but suppresses its gameplay-only world nickname and HP bar.
- `Assets/Game/Scripts/UI/MainMenu/CameraOrbit.cs`
  - Menu camera orbit driven by `UIOrbitDragArea`.
  - In `Assets/Game/Scenes/Client.unity`, it is bound to `MainMenuNew/DragImage`; this transparent image must keep `Raycast Target` enabled.
- `Assets/Game/Scripts/UI/Tree/DevelopmentTree.cs`
  - Loads `VehicleGraph` data per faction, builds the selected faction tree at runtime, and keeps purchase/research RPC validation authoritative on the server.
  - Groups every graph node by `level`: level 1 is the lowest row, later levels are stacked above it, and nodes in every row are centered.
  - A `TreeItem` click only selects a vehicle; it never starts purchase or research directly.
- `Assets/Game/Scripts/UI/Tree/FactionTreeView.cs`, `FactionButtonView.cs`, `DevelopmentTreeDetailsPanel.cs`, `ArrowDrawer.cs`
  - `FactionTreeView` owns the serialized rows and arrows layers of a generated faction tree.
  - `FactionButtonView` provides serialized faction button visuals and selects the correct background and emblem from the faction code, without runtime component lookups.
  - `DevelopmentTreeDetailsPanel` displays the selected vehicle and exclusively enables its Buy or Research button when the progression state permits it.
  - `ArrowDrawer` draws one non-interactive arrow for each server-provided `VehicleEdge` after the row layout is resolved.
- `Assets/Game/Content/UI/Prefabs/Tree/FactionTree.prefab`, `DevelopmentTreeLevelRow.prefab`, `TreeItem.prefab`
  - The first prefab provides a faction root with empty arrow and vertical-row containers; the second provides a centered, one-row horizontal grid for every level.
  - `TreeItem.prefab` remains the node visual and selection button; it is not responsible for progression actions.
- `Assets/Game/Scripts/UI/Tree/VehicleResearchProgressResolver.cs`
  - Vehicle research/progression data support.
- `Assets/Game/Scripts/UI/Settings/*.cs`
  - Settings tabs and settings model/view/controller. Their controls are authored and wired as serialized primitive UI objects in `Assets/Game/Scenes/Client.unity`; the views only bind values and events at runtime.
  - `GeneralTabView` owns the Server crosshair and Camera shake toggles, `ControlsTabView` owns gameplay and sniper mouse-sensitivity sliders, and `VideoTabView` owns FPS-limit and vertical-sync controls.
  - `Client.unity/Settings` uses Video as the visual reference for all tab controls. General toggles are centered at X `77.64`, are `322 x 32`, and retain the same checkbox/label setup as Vertical sync. Controls and Sounds sliders are centered at X `77.64`, are `322 x 40`, and have rows at Y `297`, `237`, and, for SFX, `177`; their labels are at X `-195` and use `160 x 60` bounds.
  - Every settings slider uses the same serialized frame, fill, and handle sprites as Video Gamma: `Unused/Backgrounds/Bar/loading_cell_ai_attempt_rejected.png`, `loading_cell_ai_attempt_rejected 1.png`, and `Unused/Backgrounds/icons/profile_icon_losses_skull.png`. These are presentation-only scene values; the existing tab views and serialized Slider/Toggle references remain the owners of interaction and settings values.
- `Assets/Game/Scripts/Client/ClientSettings.cs`
  - Local client runtime settings for frame pacing, projectile visuals, HUD, map, camera, reticle, auto-aim, and hover outline behavior.
- `Assets/Game/Scripts/Testing/ClientMenuTestMode.cs`
  - Scene-local offline menu test switch. In `Assets/Game/Scenes/Client.unity`, select `ClientMenuTestMode`, enable `enableOfflineMenuTest`, and edit its `testVehicles` array. Every array entry is an owned local vehicle used by the robot selector and its faction development tree; `vehicleId` values must be unique and `code` must exist in `RobotRegistry` to show its icon/preview. The saved defaults contain Iron Alliance and Nova Syndicate entries. This is for UI testing only; Free XP conversion remains disabled and the Battle/Cancel controls only open and close the matchmaking menu.
- `Assets/Game/Scripts/UI/Helpers/StartServerButtons.cs`
  - Receives the serialized `ClientMenuTestMode` reference from `Client.unity`. When its checkbox is enabled, it does not subscribe to or start FishNet networking.
- `Assets/Editor/ClientSettingsEditor.cs`
  - Custom Unity inspector for `ClientSettings`.
  - Keeps technical serialized field names visible and shows a Ukrainian explanation with a practical example as a tooltip when hovering every root and nested setting.
- `Assets/Editor/DocumentedSettingsInspector.cs`
  - Shared editor-only renderer used by settings inspectors.
  - Draws nested serialized settings recursively and provides tooltip documentation without adding description rows below fields.
- `Assets/Game/Scripts/UI/Loading/MenuLoadingScreenManager.cs`, `SharedLoadingSpinner.cs`
  - Loading screen routing, shared spinner, and FishNet scene-load progress subscription.
  - A map load keeps `MenuType.LoadScreen` above every menu/HUD for at least 2 unscaled seconds. Its presentation is deliberately independent of FishNet percentage events: the first second always fills the ten-segment bar from `0` to `0.5`; after FishNet completion, the remaining time until the two-second deadline fills `0.5` to `1.0`. The gameplay HUD is opened and initialized beneath the overlay at completion. A load that finishes after the deadline holds at `0.5`, then uses a 0.25-second final fill before closing.
- `Assets/Game/Scripts/UI/Loading/MenuLoadingProgressBar.cs`
  - Drives the ten-segment map-loading bar at `MenuLoadingScreen/AnimationPanel/Bar`. Its inspector `progress` value is clamped from 0 to 1; complete segments use `fullSprite`, the next segment uses `afterFullSprite`, and remaining segments are inactive.
- `Assets/Game/Scripts/UI/Helpers/ClockwiseUiRotator.cs`
  - Lightweight UI rotation component. A positive `rotationSpeed` rotates its RectTransform clockwise in unscaled time.
- `Assets/Game/Scripts/Audio/ButtonComponent.cs`
  - Shared UI-button behavior: plays `SFX_UI_Button_Mouse_Thick_Generic_1` on a click and keeps serialized child `Graphic` references synchronized with the Button `ColorBlock`.
  - The Button pointer/selection state drives matching child `Image` and TextMesh Pro colors for Highlighted, Pressed, Selected, and Disabled; Normal restores each child graphic's saved normal color. Color transitions use the Button `fadeDuration` and `colorMultiplier`.
  - Every Button in `Assets/Game/Scenes/Client.unity` and the game UI prefabs `GameplayHUD.prefab`, `MainMenu/VehicleSlot.prefab`, `Tree/FactionButton.prefab`, and `Tree/TreeItem.prefab` has this component with its Button and child graphics assigned in the inspector.
- `Assets/Game/Scripts/Client/ClientSettings.cs`
  - `buttonColors` owns the project-wide Button `ColorBlock` palette: normal, highlighted, pressed, selected, disabled, color multiplier, and fade duration. It is editor configuration only until applied.
- `Assets/Editor/ClientSettingsEditor.cs`, `ClientButtonColorApplier.cs`
  - The `Apply Button Colors To All UI Buttons` action in the `ClientSettings` inspector applies `buttonColors` to every Button in `Assets/Game/Scenes/Client.unity` and every prefab under `Assets/Game`, then adds or refreshes each `ButtonComponent` child-graphic reference.
  - The action asks to save modified open scenes first, saves changed assets, and restores the previously open scene setup afterwards.
- `Assets/Game/Scripts/UI/Screens/*.cs`
  - Popup/screen base infrastructure.

Important behavior:
- `MainMenu.SetActive(true)` opens `MenuType.MainMenu`; false opens `MenuType.GameplayHUD`.
- Menu transitions use only the inspector-wired `CanvasGroup` alpha and keep their authored layout positions unchanged. Each `Menu` component configures its own open/close duration with `fadeDuration`, defaulting to `0.5` seconds.
- The existing `Assets/Game/Scenes/Client.unity/Canvas/GameplayHUD` is the direct `MenuType.GameplayHUD` reference on `MenuManager`. It stays hidden while the main menu is open and is opened for gameplay; it is not spawned by `MenuManager`, and no second HUD prefab instance is allowed under the Canvas.
- In `Assets/Game/Scenes/Client.unity`, `MainMenuNew` is the routed `MenuType.MainMenu` root. Its `AnimationPanel`, `CanvasGroup`, profile fields, settings button, technology-tree button, vehicle container, and battle button are wired to the existing menu, profile, preview, and matchmaking controllers.
  - `AnimationPanel/VehicleContainer` is a native horizontal `ScrollRect` built from a transparent input `Image`, `RectMask2D`, and the `Content` child. `Content` exclusively owns `HorizontalLayoutGroup` and `ContentSizeFitter`; generated vehicle slots are its direct children. The `RectMask2D` clips off-screen cards without the stencil-mask dependency that can hide every card. Drag the list or use the mouse wheel to reveal additional robots. While selecting or loading another owned robot, `RobotView` preserves the current scroll position and refreshes matching slot/card views in place; it only creates or removes a slot/card when that vehicle has been added to or removed from the available list.
  - `RobotView` keeps `RobotViewGenerator/RobotPlatform` active while profile data or a newly selected preview robot loads, so its camera environment never flashes black. `RobotView.Despawn()` hides the platform only for the transition from the main menu to gameplay; `RobotPlatform` is active in the saved Client scene for the initial menu load as well.
- The settings listener is bound to `MainMenuNew/AnimationPanel/TopPanel/SettingsBack/Settings`, the button that receives the UI click.
- The selected vehicle's name, faction, tier icon, XP, armor, mobility, firepower, and calculated average DPS are shown continuously in `MainMenuNew/AnimationPanel/RightPanel`. The panel is updated from the profile's selected vehicle after the vehicle list and API stats load; it is not shown only while hovering a slot.
- Settings and development tree buttons use `MenuManager.OpenMenu`.
- In `Assets/Game/Scenes/Client.unity`, the existing `MenuType.DevelopmentTree` route now opens `DevelopmentTreeNew`.
  - `DevelopmentTreeNew/AnimationPanel/FactionRoot` and `ButtonsContainer` must stay empty in the saved scene: `DevelopmentTree` fills them from server data.
  - Generated faction buttons use the `DevelopmentTreeNewView` visual reference: Iron Alliance uses `nav_button_a_bg_v2` with `emblem_a`; Nova Syndicate uses `nav_button_gear_bg` with `tree_sidebar_gear`.
  - The right-side `RightInfoPanel` is static layout only. `DevelopmentTreeDetailsPanel` updates its `Tier/lvl` image from the serialized I–X tier sprites after a node is selected.
  - `DevelopmentTree` registers `CloseBattle` at runtime through its serialized `buttonBack` reference. `DevelopmentTreeCloseButton` also closes on left-pointer-down and verifies the left mouse press is inside its own `RectTransform`, so the control still closes when Unity does not emit the legacy `Button.onClick`. The panel root is hidden before the main-menu route opens.
  - Owned vehicles disable both actions; researched but unowned vehicles enable only Buy; vehicles with an affordable owned predecessor enable only Research.
- In `Assets/Game/Scenes/Client.unity`, `MenuLoadingScreen/AnimationPanel/Bar` has `MenuLoadingProgressBar` with its ten `element (0-9)` images and the `full` / `after full` sprites assigned. At progress `0.5`, elements 0-4 are full, element 5 is the after-full sprite, and elements 6-9 are hidden; at `1.0`, all ten elements are full.
- `MenuLoadingScreenManager` receives FishNet `OnLoadStart` and `OnLoadEnd` for the active `LoadQueueData`. It resets the bar to `0`, animates `0→0.5` over the first unscaled second, waits at `0.5` until the load ends, then animates `0.5→1.0` over the remainder of the two-second minimum. If the map is still loading after two seconds, the final fill takes 0.25 seconds after `OnLoadEnd`. It opens `GameplayHUD` beneath the overlay at completion and closes the overlay immediately after its final fill. Events from a different queued load are ignored, so a later operation cannot overwrite the current bar.
- In `Assets/Game/Scenes/Client.unity`, `FreeXpConversionPopup` is an initially inactive primitive UI popup under the main Canvas. Its serialized references include the vehicle-dropdown button, scrollable option-template container, whole-number slider, Convert button, and Close button; `MainMenu` is wired to the existing `freeXp` control Button.
- Gameplay input blocking is tied to menu state in `VehicleInputController.IsGameplayInputBlockedByUi`.
- Offline menu test flow: `ClientMenuTestMode` is enabled in the Client scene -> `StartServerButtons` does not start a connection -> `ClientMenuTestMode.Start` opens `MainMenu` -> `ProfileServer.UpdateProfile` creates an owned local profile from `testVehicles` -> `RobotView` builds each selector slot and changes the local selected vehicle -> `DevelopmentTree` groups the same data by `factionCode` and builds one tree per faction without HTTP or RPC calls.
- `Assets/Game/Scenes/Client.unity` keeps the `FindGame` root inactive until its routed menu opens. Its `AnimationPanel/panel/arrow` uses `ClockwiseUiRotator` with `rotationSpeed: 120`.

Rules when editing menus:
- Author every new static menu, popup, and settings control manually from Unity UI objects in `Assets/Game/Scenes/Client.unity` (or in its owning UI prefab), then assign its dependencies through serialized inspector references.
- Runtime UI views may bind data, visibility, and events only. Do not create static controls with `new GameObject` or `AddComponent`, and do not locate required UI controls through `Find` or `GetComponent` calls.
- Keep menu state changes consistent with gameplay input blocking.
- Do not let menu-only code affect server-authoritative gameplay.
- If profile fields or vehicle selection changes, update `api-resources.md` too.
- If gameplay HUD behavior changes, update `ui-hud.md`.
- Add a Ukrainian explanation with a practical example to `Assets/Editor/ClientSettingsEditor.cs` whenever `ClientSettings` gains a serialized field, including nested settings.
