# Robot Control

Read this file before changing vehicle input, movement, turret rotation, gun pitch, aim solving, runtime stats, or vehicle prefab contracts.

Current owner scripts:
- `Assets/Game/Scripts/Gameplay/Robots/VehicleRoot.cs`
  - Central reference hub for a vehicle prefab.
  - Holds inspector-wired references to input, movement, health, turret, weapon, gun recoil, HUD, client visibility, bot brain, centralized armor, and vehicle-specific animation/presentation controllers.
  - Applies `IVehicleRootAware`, `IVehicleInitializable`, and `IVehicleStatsConsumer` to configured components.
  - Tracks `LocalPlayerVehicle` and active vehicles.
- `Assets/Game/Scripts/Gameplay/Robots/VehicleHUD.cs`
  - Robot-owned world HP/vehicle-name HUD component referenced by `VehicleRoot.vehicleHUD`.
  - Rotates the world HP bar to face the gameplay camera and applies distance scaling from `GameplayRuntimeSettings`.
  - Refreshes HP fill immediately during root binding/spawn and on `VehicleHealth.OnHealthChanged`/damage events.
  - Consumes runtime vehicle stats to display the robot name, with code and prefab instance name as fallbacks.
  - Uses overlay materials assigned by `Assets/Game/NameCanvas.prefab`, so its name and HP images render through walls.
  - Uses `VehicleClientVisibility` for activation: it disappears with the robot's map marker, but while active its overlay materials render through walls.
  - Suppresses its complete world-space presentation on the local owner's gameplay vehicle, independently of spotting updates and nickname initialization.
  - Suppresses the same world-space presentation for menu-preview vehicles after `VehicleRoot.Init(true)`.
- `Assets/Game/Scripts/Gameplay/Robots/VehicleClientVisibility.cs`
  - Owns client-side rendering visibility for a spawned vehicle without changing network/gameplay activation.
  - On a server-only spawn, destroys the GameObjects that own every inspector-wired `visualRenderers` entry. This removes robot model meshes, wheel meshes, and track renderers from the dedicated server while leaving functional transforms, colliders, armor, and movement components intact.
  - Server visual stripping is skipped for a host process because the local client still needs the model.
  - Treats direct enemy spotting and spotted-memory map presence as visible, so the model disappears exactly when the map marker disappears.
  - Supports a non-serialized visibility override for isolated test harnesses. `VehicleTestSceneController` forces its spawned vehicles visible because it does not receive normal match visibility snapshots; live matches continue to use map visibility.
  - Requires every visual `Renderer` to be assigned in `visualRenderers`; hidden enemies are suppressed with `forceRenderingOff`.
  - On vehicle death, freezes the visibility state that was active at that moment and stops processing later spotting updates. Visible debris therefore stays rendered after detaching, while a vehicle that was already hidden does not reveal its death position.
  - Registered robot prefabs under `Assets/Game/Content/Robots/IA` and `Assets/Game/Content/Robots/NV` own the serialized component, `VehicleRoot.clientVisibility` reference, and complete renderer lists.
  - Applies its first client visibility result immediately from `OnStartClient`, preventing an unconfirmed remote vehicle from rendering for an initial frame.
- `Assets/Game/Scripts/Gameplay/Robots/DeathLogic.cs`
  - After a client receives a vehicle death event, keeps the detached debris for `VehicleHealth.DeathDebrisDelaySeconds` (`5` seconds), then fades its renderer material instances over `VehicleHealth.DeathDebrisFadeDurationSeconds` (`1` second) using URP transparent blending.
  - Disables the detached debris colliders and destroys the detached GameObjects as soon as the fade completes. It also performs that cleanup if the vehicle is removed earlier, so a map transition or external despawn cannot leave local debris behind.
  - Every registered IA/NV robot prefab assigns each non-armor `MeshRenderer` object as a `detachableVisuals` entry. That object owns its disabled convex `MeshCollider`, kinematic `Rigidbody`, and renderer; parent-level debris rigidbodies and mesh colliders are not used. `DeathLogic` registers each mesh-collider/renderer pair with `VehicleColliderRegistry`, allowing a robot impact projector to target only the visual part that was hit. Meshes under `Armor` are editor-only and are never added to the death list or made visible by death handling.
  - On death, `DeathLogic` detaches each configured renderer object, enables its collider, switches its rigidbody to dynamic, and preserves the renderer visibility state captured by `VehicleClientVisibility`.
- `Assets/Game/Scripts/Gameplay/Robots/VehicleHealth.cs`
  - The server owns post-death removal. After marking the vehicle dead and notifying observers, it waits for the same debris delay and fade duration plus a `0.25` second network safety margin, then calls FishNet `ServerManager.Despawn` on the vehicle `NetworkObject`.
- `Assets/Game/Scripts/Gameplay/Robots/VehicleAutoAimController.cs`
  - Rejects enemies hidden by `VehicleClientVisibility`, including an already locked target after its direct spotting expires.
- `Assets/Game/Scripts/Gameplay/Robots/VehicleHoverOutline.cs`
  - Rejects hidden enemies and clears an active outline when the visibility presenter hides its vehicle.
  - Draws only the inspector-wired `outlineRenderers` list. Every visible body, turret, gun, wheel, and track renderer must be in that list, with a matching `outlineSubMeshCounts` entry, or that element cannot receive the hover outline.
  - Armor collision renderers and the vehicle world HUD are excluded from the outline list.
- `Assets/Game/Scripts/Gameplay/Robots/VehicleInputController.cs`
  - Handles owner local input and server external input.
  - Owner local input supports World of Tanks-style cruise control as one signed speed level from `-3` to `3`: `R` adds one forward step, `F` adds one reverse step, and each step maps to `1/3` of `Move.y`.
  - Manual `W`/`S`, `Space`, or blocked UI/gameplay input clears cruise control before movement is sent to the server.
  - Implements `IBotInputReceiver` for bot movement.
  - Applies server input to movement, shoot/action state, turret yaw, gun pitch, and desired aim point.
- `Assets/Game/Scripts/Gameplay/Robots/CameraController.cs`
  - Owns local gameplay camera orbit, zoom steps, and sniper camera placement.
  - Reads `GameplayRuntimeSettings.cameraZoomDefault`, `cameraZoomForwardSteps`, and `cameraZoomBackwardSteps`. Step `0` is default; forward array element `0` is the first wheel-forward step, backward array element `0` is the first wheel-backward step, and every profile stores absolute camera distance, absolute vertical FOV, base reticle diameter, reticle multiplier, and `showReticle`. Every forward profile with `showReticle = true` activates the black sniper-scope circle and central reticle; the ordinary projectile-dispersion ring remains separate. The first flagged forward profile is used by the explicit sniper toggle, but the wheel can continue through all flagged profiles. There is no separate sniper zoom profile. The base reticle diameter is a visual floor only; it is not a multiplier for the current/minimum dispersion ratio.
  - Sends the clamped signed `_currentZoomStep` to `GameplayGUI`; the HUD displays `0` for default, negative values for backward wheel steps, positive values for forward wheel steps, and the sniper profile at the next positive step.
  - During FOV smoothing the current camera FOV remains authoritative; the weapon reticle does not use a normalized distance approximation. The active profile's `cameraDistance` is refreshed every camera update, so runtime profile edits are applied even without another wheel event; normal orbit profiles use it from `CameraRig`, and the sniper profile adds it to the inspector-wired sniper forward offset from its selected anchor.
  - Delegates the final camera position to its inspector-wired `CameraCollisionController` before gameplay-camera synchronization, so aiming uses the collision-corrected camera origin.
  - When entering sniper mode, aligns the camera yaw/pitch from the sniper anchor to the current gun aim point before moving the camera, so Shift/scroll zoom does not retarget the gun lower because of camera-origin parallax.
  - When exiting sniper mode, aligns the camera yaw/pitch from the normal orbit pivot (`rig.position`) to the current gun aim point before restoring the third-person zoom, so the gun does not climb upward when the camera origin changes back.
- `Assets/Game/Scripts/Gameplay/Robots/Shared/DispersionConeProjection.cs`
  - Contains the shared `DispersionConeProjection` helper in `Game.Gameplay.Shared` so the shot, reticle, and focused tests use one cone-basis implementation without an extra runtime component.
- `Assets/Game/Scripts/Gameplay/Robots/CameraCollisionController.cs`
  - Client-side camera collision helper placed with `CameraController` on each vehicle's `CameraPoint` or `CameraFlyPoint`.
  - Sphere-casts from the controller's `rig` toward its desired camera position, ignores colliders below the inspector-wired local `VehicleRoot`, and moves the camera immediately in front of the nearest blocking surface.
  - Uses a reusable non-alloc hit buffer, ignores trigger colliders, and smoothly restores distance at `recoverySpeed` once a surface no longer blocks the view.
- `Assets/Game/Scripts/Gameplay/Robots/VehicleServerInput.cs`
  - Small struct for server-side movement/combat input.
  - `Movement` carries movement only.
  - `Combat` carries movement plus shoot/action and aim state.
- `Assets/Game/Scripts/Gameplay/Robots/VehicleMovementController.cs`
  - Server-side movement simulation on FishNet ticks.
  - Reads `vehicleRoot.inputManager.Move` and drives a `CharacterController`.
  - Caps reverse movement at 50% of forward max speed for all vehicles, including human input, cruise control, and bot input.
  - Applies runtime stats for speed, acceleration, traverse speed, and hull traverse acceleration.
  - Releasing forward/reverse input coasts to zero using the faction-specific server setting: `nvStoppingAccelerationMultiplier` for NV and `iaStoppingAccelerationMultiplier` for IA. These are braking-strength multipliers, so higher values mean less inertia. The current profile is NV `10.0` and IA `2.0`, five times softer than the previous `50.0`/`10.0` profile and ten times stronger than the original neutral stopping profile. Same-direction speed reduction uses the chassis-class braking multiplier; an actual direction reversal uses `directionReversalBrakingMultiplier` plus the faction stopping multiplier. The current reversal value `2.0` makes the stopping distance approximately half of neutral coasting.
  - When API `traverseAcceleration` is positive, non-NV hulls accelerate the signed yaw speed toward input × `traverseSpeed` each tick and decelerate it toward zero without turn input. The movement controller applies a `2×` traverse-acceleration multiplier; turret rotation continues to use only `turretTraverseSpeed`.
  - `RobotFaction.NovaSyndicate` (NV) ignores `traverseAcceleration` and retains the legacy immediate hull-turn behavior. A missing or zero value does the same for every faction.
- `Assets/Game/Scripts/Gameplay/Robots/VehicleGroundAlignmentController.cs`
  - Samples downward raycasts, averages their surface normals and hit distances, and is the only controller that writes rotation to each configured ground-aligned target.
  - Optionally passes the resolved normal, rotation, and average hit distance to `VehicleBodySwayController`, then composes its target-local offset after resolving ground rotation so terrain alignment and body sway cannot overwrite each other.
- `Assets/Game/Scripts/Gameplay/Robots/VehicleBodySwayController.cs`
  - IA tracked-robot presentation component placed on the main prefab root and referenced by `VehicleRoot.bodySwayController`.
  - Runs only for the local gameplay owner (`VehicleRoot.IsOwner` and not `IsMenu`). Remote players and bots return the identity rotation offset, so their local clients do not simulate body sway.
  - Converts acceleration, braking, and reversals into a transient local pitch target. It also derives pitch/roll impulses from changes in the averaged ground normal and derives a forward/reverse pitch impulse from changes in average ground distance.
  - Simulates those presentation targets with a bounded spring and damping; it never writes a transform or network state itself. `VehicleGroundAlignmentController` continues normal terrain alignment for every vehicle.
- `Assets/Game/Scripts/Gameplay/Robots/VehicleBodyVerticalSpringController.cs`
  - Presentation component placed directly on every robot's `Body` turret pivot and referenced by `VehicleRoot.bodyVerticalSpringController`.
  - Runs only for the local gameplay owner (`VehicleRoot.IsOwner` and not `IsMenu`); it resets its offset for all remote players and bots.
  - Samples the assigned `Chassis` transform's world Y position in `LateUpdate`. A rise makes the turret lag down; a drop makes it lag up. The resulting change in chassis vertical velocity is transferred into the turret spring, so bumps, crests, and holes drive the response without reacting to movement input.
  - Ignores small vertical-speed noise, caps one-frame speed changes, and discards implausibly large chassis speeds as teleports/network corrections before simulating its bounded local Y offset. It never writes a transform, rotation, root position, input, or network state itself.
- `Assets/Game/Scripts/Gameplay/Robots/PositionSync.cs`
  - Remains the sole position writer for its target transform, including every robot `Body` turret pivot.
  - When `bodyVerticalSpringController` is assigned, it adds the spring's Y offset to its existing target-space offset before applying the position. This prevents `PositionSync` and the spring from overwriting each other.
  - Restores the authored local Y position when disabled or when the vehicle dies, so it remains isolated from turret aiming, ground alignment, and walker animation.
- `Assets/Game/Scripts/Gameplay/Robots/VehicleTurretRotationController.cs`
  - Turret yaw controller.
- `Assets/Game/Scripts/Gameplay/Robots/WeaponAimController.cs`
  - Gun pitch and aim point controller.
  - Resolves camera/gun aim rays and pitch constraints.
- `Assets/Game/Scripts/Gameplay/Robots/VehicleGunRecoilController.cs`
  - Root-level, client-side gun presentation controller.
  - On an approved/predicted visual shot, moves its inspector-wired `gun` backward along the gun's current rotated local `-Z` axis at `recoilSpeed`, holds for `returnDelay`, then smoothly returns it to the authored local position with `returnSpeed`.
  - Does not change aim, projectile origin, hit resolution, network state, or damage. `DeathLogic` stops it before detaching debris, and it also ignores an already-dead vehicle, so it cannot overwrite detached gun physics.
- `Assets/Game/Scripts/Gameplay/Robots/VehicleAimInputSolver.cs`
  - Converts an aim point/forward direction into target turret yaw and gun pitch.
- `Assets/Game/Scripts/Gameplay/Robots/VehicleRuntimeStats.cs`
  - Runtime stat values, API faction mapping through `RobotFaction`, and default stat resolution helpers.
- `Assets/Game/Scripts/Gameplay/Robots/VehicleStatsProvider.cs`
  - Async stat lookup for spawned vehicles.
- `Assets/Game/Scripts/Gameplay/Robots/VehicleNetworkInitializer.cs`
  - Initializes player/bot identity, team, scene, and owner/menu setup.
  - Carries the server-authored synchronized kill count used by gameplay player-list HUD rows.
  - Publishes a client team-change notification so vehicle visibility refreshes after post-spawn FishNet `Team` SyncVar updates.

Input flow:
- Human owner input is read by `VehicleInputController.Update` and sent to server RPCs.
- For human owner movement, `W`/`S` still send full forward/reverse input; cruise control sends fractional `Move.y` values from local `R`/`F` state without changing the server input struct.
- Server authoritative movement reads `VehicleInputController.Move` from `VehicleMovementController`; negative `Move.y` is always simulated with the 50% reverse speed cap.
- Bots use the same input channel through `VehicleInputController.ApplyBotInput` and `ServerSetExternalInput`.
- Combat/idle aim uses `VehicleServerInput.Combat` with `HasAim = true`.
- Movement-only bot input preserves current shoot/action state and does not clear aim when `HasAim = false`.

Aiming flow:
- Aim requests are solved through `VehicleAimInputSolver`.
- `VehicleInputController.ServerSetExternalInput` applies desired aim point/forward, target pitch, and target yaw.
- Turret and gun constraints are respected by the existing controllers.

Prefab/reference rule:
- `VehicleRoot` references should be assigned in prefab/scene inspector.
- Every registered IA and NV battle-vehicle prefab has one enabled `CameraCollisionController` on the same object as `CameraController`; `CameraController.collisionController` must reference it and `CameraCollisionController.ignoredVehicle` must reference that prefab's root `VehicleRoot`. Its default `collisionMask` excludes the Ignore Raycast layer, `collisionRadius` is `0.3`, `surfacePadding` is `0.08`, and `recoverySpeed` is `24`.
- Battle vehicle prefabs must assign `VehicleRoot.clientVisibility` and every model renderer in `VehicleClientVisibility.visualRenderers`; missing renderer entries can leak hidden geometry.
- Every registered IA and NV battle-vehicle prefab has one enabled `VehicleGunRecoilController` on its main vehicle object. `VehicleRoot.gunRecoilController` references it and its `gun` references the same transform as `WeaponAimController.gun`. The default tank-style values are `recoilDistance` `0.18`, `recoilSpeed` `3`, `returnDelay` `0.04`, and `returnSpeed` `0.75`; tune these presentation values per robot without changing firing or projectile settings.
- Battle vehicle prefabs must also assign every non-armor `MeshRenderer` and `SkinnedMeshRenderer` to `VehicleHoverOutline.outlineRenderers`. `outlineSubMeshCounts` must match each renderer's current mesh submesh count; missing entries make only a subset of the robot glow on hover.
- Every IA prefab under `Assets/Game/Content/Robots/IA` has one enabled root `VehicleBodySwayController`; `VehicleRoot.bodySwayController` and the `Root` target in `VehicleGroundAlignmentController.targets` both point to that same component. Do not place a second sway component on `Root` or `ParentRoot`.
- The default IA sway tuning is `2` degrees for acceleration, `3` degrees for braking, a `4`-degree total pitch limit, input responses `4`/`8`, spring strength `60`, damping `12`, and maximum pitch speed `90`. `maximumSimulationStep` bounds the simulation after a frame hitch.
- Terrain tuning is prefab-local: `terrainAngularSpeedDeadZone` ignores small normal noise; the two `DegreesPerAngularSpeed` fields convert a normal change in degrees/second to body pitch/roll; `terrainPitchDegreesPerVerticalSpeed` responds to average ray-hit distance in metres/second while moving. `maxTerrainPitchDegrees` and `maxTerrainRollDegrees` bound the terrain contribution. The IA defaults are `5`, `0.025`, `0.025`, `0.75`, `2`, and `2` respectively.
- Every registered IA and NV prefab has exactly one enabled `VehicleBodyVerticalSpringController` on its `Body` object, and `VehicleRoot.bodyVerticalSpringController` points to it. Its `chassis` must reference the parent of that `Body` object's `PositionSync.target` (`ChassisT2` for IA, `ChassisMain` for NV). It is independent from the root `VehicleBodySwayController`, which remains IA-only.
- Every such `Body` also assigns that same component to `PositionSync.bodyVerticalSpringController`. Do not add any other `Transform.position` or `Transform.localPosition` writer to `Body`.
- The vertical spring defaults are `verticalSpeedDeadZone` `0.05`, `verticalSpeedChangeDeadZone` `0.1`, `maximumChassisVerticalSpeed` `8`, `maximumChassisVerticalSpeedChange` `3`, `chassisVerticalSpeedTransfer` `1.2`, `maxUpwardOffset` `0.02`, `maxDownwardOffset` `0.02`, `springStrength` `45`, `damping` `6`, `maxVerticalSpeed` `4`, `endStopRebound` `0.35`, and `maximumSimulationStep` `0.05`. Positive and negative local Y are both limited to `2 cm`; when either limit is reached, `endStopRebound` reverses a controlled fraction of the speed instead of discarding it, so the turret keeps its short spring response. Set it to `0` for a fully dead stop or increase it (up to `1`) for a livelier rebound.
- `Body` FishNet `NetworkTransform` components synchronize rotation only. Keep their position synchronization disabled: the vertical spring is a local visual offset, not replicated movement.
- Registered robot debris uses each non-armor rendered mesh object as the physics root. Each non-armor `MeshRenderer` object owns its `MeshFilter`, disabled convex `MeshCollider`, and kinematic `Rigidbody`; parent mesh holders no longer own debris rigidbodies or mesh colliders. The collider uses the same mesh assigned to that object's `MeshFilter`. Armor `MeshRenderer` objects retain only their editor geometry and armor collider setup.
- Unity's convex MeshCollider limit is 255 source triangles; higher-poly robot meshes keep `convex` enabled and Unity cooks a partial convex hull. A future visual-accuracy pass should provide authored low-poly proxy meshes for those specific parts rather than reintroducing parent-level physics.
- IA and NV prefab transform paths remain unchanged for animation and gameplay references. `VehicleClientVisibility`, `VehicleHoverOutline`, and `DeathLogic.detachableVisuals` all point to the same mesh-renderer objects, so death detaches exactly the objects that are rendered.
- T1 Hunter armor is separate from visuals and debris. It has eight damage surfaces: three turret/gun cubes below `Body` and five hull/leg cubes below `Chassis/ChassisMain`. Child surfaces contain only Unity components; the root `VehicleArmorController` owns the two armor arrays and runtime registration.
- T1 Hunter walking is owned by one root `WalkerAnimationController`. It contains both foot references, ground placement settings, step animation, and body bobbing. When neither walking nor turn input exceeds `inputThreshold`, it preserves each halted foot's world X/Z and its step weights, then raycasts down and interpolates its Y to ground level plus `footOffset` over `0.4` seconds. When movement resumes, it interpolates the foot's Y from that ground pose to the active step height over the same `0.4` seconds, instead of snapping to it or blending targets back to their neutral center. One root `VehicleGroundAlignmentController` owns all three ground-aligned transforms.
- `Assets/Game/Content/Robots/NV/NV_L2_Scout/NV_L2_Scout.prefab` uses two `TwoBoneIKConstraint` chains rooted at `legUpR` and `legUpL`. Its foot targets and bend hints must stay aligned with their respective upper-leg X positions: `RFootTargetCinematic` and `KonRCinematic` at `0.343`; `LFootTargetCinematic` and `KonLCinematic` at `-0.343`. If those values remain at the inherited wider stance, turning in place makes the IK solver choose divergent 3D leg poses.
- `Assets/Editor/VehiclePrefabIntegrityEditor.cs` validates every robot registered by `Assets/Game/Content/Configuration/Robots/RobotRegistry.asset` and queues a repair after Unity imports a registered robot prefab, its base prefab, or recompiles editor scripts.
  - The repair pass restores `VehicleRoot` references only when exactly one matching component already exists in the prefab hierarchy. It rebuilds both `VehicleClientVisibility.visualRenderers` and `VehicleHoverOutline.outlineRenderers`/`outlineSubMeshCounts` from every non-armor `MeshRenderer` or `SkinnedMeshRenderer`, excluding the vehicle HUD; this keeps hidden-vehicle suppression, server-only visual stripping, and hover outlines aligned. It also restores the IA-only `VehicleBodySwayController` reference, the all-robot `VehicleBodyVerticalSpringController`, its `chassis` reference from the parent of `PositionSync.target`, and `PositionSync.bodyVerticalSpringController` references, `VehicleMovementController.controller`, `VehicleBotBrain.navigator`, serialized `IVehicleRootAware` root links, and walker IK target/hint X coordinates when they share the upper-leg root's parent. When an existing `MeshCollider` has a broken mesh reference, it binds the nearest unique visual mesh; an exact direct child named `VisualMesh` takes priority. A broken direct `VisualMesh` filter binds the nearest unique sibling visual mesh. Ambiguous mesh sources remain validation errors.
- For IA tracked prefabs, the same repair pass rebuilds `TrackedVehicleAnimator.leftWheels` and `rightWheels` from the current `WheelA1` parents below `LeftWhels` and `RightWhels`, adds missing per-mesh disabled convex `MeshCollider` and kinematic `Rigidbody` components to non-armor rendered mesh objects, and rebuilds matching `DeathLogic.detachableVisuals` entries. The wheel mesh collider uses the matching `MeshFilter.sharedMesh`; no wheel transform or authored position is written by this repair.
- Missing, duplicate, or configuration-dependent components are reported instead of being created with unsafe defaults. Use `Tools/WOM/Robots/Validate Registered Prefabs` for a read-only report or `Tools/WOM/Robots/Repair Registered Prefabs` for a full repair followed by validation. CI and headless checks can call `Game.Scripts.Editor.VehiclePrefabIntegrityBatch.RepairAndValidate` through Unity `-executeMethod`.
- Root walker, tracked, suspension, and ground-alignment controllers stop updating when `VehicleHealth.IsDead`; `DeathLogic` also disables them before debris detachment. Body-sway and body-vertical-spring additionally skip their presentation simulation for all non-owners and menu previews.
- IA tracked robot prefab parents (`CabineReal`, `WeaponReal`, `MeshReal`, and wheel holders) are transform/animation owners only. Their mesh-renderer children own the disabled convex `MeshCollider` and kinematic `Rigidbody` used by death debris, so no parent debris collider can overlap the live layer-7 `CharacterController`.
- T2 armor is separate from visuals: all 13 damage colliders are children of the three objects named `Armor` (six hull colliders, six turret colliders, and one gun collider). One root `VehicleArmorController` owns those arrays plus the registry-only `ChassisT2` collider. Armor renderers are disabled and are not included in visual visibility/outline lists.
- T1 Hunter and T2 configure their armor renderers in `VehicleArmorController.serverEditorArmorRenderers`. A server-only process running in the Unity Editor enables those renderers after spawn so server armor geometry remains visible for inspection. Player builds do not enable armor rendering.
- `VehicleRoot.OnStartServer` owns the server-only presentation transition: it enables Editor armor visualization, then asks `VehicleClientVisibility` to destroy configured model visual objects.
- The old T2 primary meshes `MeshBody`, `MeshGun`, `MeshR`, the old root armor mesh, and all `WhelMesh`/`WheMesh` wheel instances are removed.
- T2 wheels use one centered functional `WheelA1_01..04` or `WheelA2_01..07` parent directly below `LeftWhels`/`RightWhels`, followed by the nested `a1`/`a2` mesh. The redundant numeric A1 holder level is removed. `TrackedVehicleAnimator` must reference every current `WheelA1` parent: arrays use `+900` on the left and `-900` on the right so mirrored wheel meshes roll in the same physical direction. Track UVs negate longitudinal `AnimMove.y`, while wheel meshes use its original sign; both use the same turn input. The animator therefore resolves separate track and wheel speed pairs: forward/reverse animation has the correct direction for each visual type, and pivot turns retain their correct direction. Current IA arrays are four wheels per side on `IA_L1_Starter`, `IA_L2_Colossus`, and `IA_L2_Guardian`, and six wheels per side on `IA_L2_Scout`; the counts come from the actual left/right hierarchy rather than stale serialized array padding.
- Wheel suspension and animation still reference the authored wheel parents, but death physics is owned by each wheel `MeshRenderer` child. The child collider remains disabled while alive and is enabled only by `DeathLogic`.
- One root `CaterpillarSuspensionController` owns all 74 suspension targets. Raycast settings are shared and each target retains only its required position offset.
- T2 tracks remain visual-only and use the enabled `CaterpillarTrackLeft/Cube` and `CaterpillarTrackRight/Cube` skinned renderers from `t2v2.fbx`. The obsolete hidden `Mesh` physics duplicates are not part of the prefab.
- On IA death, all configured mesh-renderer objects detach and become dynamic. The centralized tracked animator stops when vehicle health is dead. Track roots without `MeshRenderer` remain visual-only and are deactivated instead of becoming debris.
- Do not add runtime component discovery for required vehicle parts.
- If a new vehicle subsystem is needed, add serialized/configured references and validate missing configuration with clear errors.

Known failure: apparent network movement caused by prefab colliders:
- Recorded case: `T2-RM` moved backward uncontrollably and could be pushed out of the map immediately after entering a match. Menu preview rendering remained correct.
- This can look like FishNet desync or bad network movement because the server-authoritative `VehicleMovementController` uses a `CharacterController`, then FishNet replicates the resulting server transform. FishNet can therefore expose the movement without being its cause.
- In the recorded case, diagnostics reported `0%` packet loss. The actual cause was that convex debris colliders were enabled while the robot was alive and overlapped the layer-7 `CharacterController`. Unity physics depenetration moved the server vehicle, and FishNet synchronized that movement to clients.
- Required registered-prefab state: every mesh-renderer debris collider is disabled while alive and is assigned to the matching `DeathLogic.detachableVisuals` entry. `DeathLogic` enables configured debris colliders only after death.
- `RobotRegistry` selects the prefab but does not own this movement behavior. For this symptom, inspect the selected vehicle prefab, `VehicleMovementController`, `CharacterController`, debris colliders, and `DeathLogic` before changing registry or FishNet code.
- If this symptom returns, run the mandatory diagnostics workflow first. When packet loss and network health are normal, inspect for enabled colliders overlapping the root `CharacterController`, a non-zero prefab root transform, and missing `DeathLogic` references. After correction, restart Play Mode, reproduce a match, and run `./game-diag.cmd analyze --last 30`.

When changing this mechanic:
- Update this file if input shape, aim solving, vehicle references, movement authority, or stats consumption changes.
- Update `ai-bots.md` if bot input behavior changes.
- Update `weapons-damage.md` if shoot/reload/fire input changes.
